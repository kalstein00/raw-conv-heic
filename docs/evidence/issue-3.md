# #3 — 대표 장면 비교와 Fold7 전달 자료

이 문서는 대표 비교 파일을 준비하는 Phase 0A 결과다. 실제 Fold7 HDR 표시와 최종 사용자 화질 승인은 #4에서 별도로 확인한다. 개인 사진은 `artifacts/`에만 저장하며 GitHub에 업로드하지 않는다.

## 선정과 빠진 장면

제공된 37장의 ARW embedded JPEG contact sheet를 육안 확인했다. 전체 RAW 배치 변환은 하지 않았다.

| 대표 입력 | 관찰한 장면 / 확인할 항목 |
| --- | --- |
| DSC07773 | 그늘 속 인물과 밝은 나뭇잎 틈; 피부색·그림자·세로 방향 |
| DSC07793 | 꽃과 부드러운 배경; 색·배경 계조·과도한 HDR 확대 방지 |
| DSC07796 | 푸른 하늘·흰 구름·어두운 나무; 하이라이트·색·밴딩 |
| DSC07805 | 햇빛 아래 인물 근접; 피부색·WB·명암 |
| DSC07809 | 밝은 배경과 그늘 속 인물·나무; 역광성 대비와 세로 방향 |

야경/고ISO 밤 장면은 없었다. 야경 노이즈·점광원 수용에는 추가 ARW/HIF가 필요하며 현재 자료로 통과했다고 하지 않는다. DSC07809는 밝은 배경/그늘의 대비 장면이며 강한 태양 역광·렌즈 플레어 전체를 대표하지 않는다.

## 기본 톤 변경

#2의 전역 4배 노출·Reinhard SDR은 파일 생성 경로를 확인하는 임시값이었다. #3의 `highlight-only-v1`은 선형 RGB16에서 현상 밝기 0.25를 되돌린 neutral RGB를 만든다. SDR은 그 RGB를 sRGB로 인코딩한다. HDR은 선형 luminance 0.5 이하에서 같은 RGB를 유지하고, 밝은 영역에서 부드럽게 최대 4배까지 확장한다. 세 채널에 같은 배율을 적용해 색 비율을 유지한다. 밝은 영역의 톤 배분이며 RAW에 없던 세부 묘사 복원을 주장하지 않는다.

인코더 Gain Map 범위는 1~4배로 고정한다. 어두운 장면의 실제 픽셀을 억지로 1 이상으로 키우지 않는다. 구조·디코딩·복원이 유효하면 HDR 차이가 작은 장면도 성공할 수 있으며 `has_pixels_above_sdr_white`를 별도 보고한다. 대표 인물 회귀 기준은 독립 복원한 shadow luminance<0.25 영역의 RGB 평균 절대 변화량 <0.01이다.

`convert_raw`가 같은 고정밀 SDR/HDR 의도에서 비교용 JPEG를 선택적으로 생성한다. 이 경로는 개발 비교 자료용으로 GUI 출력 선택지가 아니다. HEIC는 독립 BMFF/FFmpeg/NumPy 검사 후에만 게시한다. 비교 JPEG는 Pillow의 SDR 디코딩과 libultrahdr 자체 metadata probe를 확인하며 **독립 HDR 검증으로 부르지 않는다**.

## 재현과 파일

#2 네이티브 빌드가 필요하다. 추가 Python 의존성은 comparison extra의 pillow-heif 1.8.1이며 카메라 HIF 비교에만 쓴다. 실제 HIF의 NCLX는 BT.709/sRGB이고 10bit YUV 4:2:2다. HIF가 HDR이라고 가정하지 않는다. HIF 색 프로필이 이 관측과 다르면 미리보기 생성은 거부한다.

```powershell
uv sync --locked --extra dev --extra comparison
.venv/Scripts/python.exe scripts/contact-sheet.py C:/path/to/private-samples artifacts/issue-3/contact.jpg
.venv/Scripts/python.exe scripts/prepare-comparison.py C:/path/to/private-samples artifacts/issue-3/representatives DSC07773 DSC07793 DSC07796 DSC07805 DSC07809
```

대상 폴더가 이미 있으면 덮어쓰지 않고 실패한다. 실패 후 재실행은 새로운 대상 폴더를 지정한다. 성공한 개별 파일이 남아 있어도 완전한 묶음의 성공으로 간주하지 않는다. 전체 성공 시 `index.html`이 생긴다.

각 샘플 폴더에는 원본 HIF 사본, 생성 HEIC, 비교용 Ultra HDR JPEG, 카메라 SDR PNG, 변환 SDR PNG, 독립 HDR 복원의 -2EV 진단 PNG, `report.json`이 있다. 카메라/변환 SDR PNG는 전체 해상도이며 클릭해서 실제 픽셀을 확인할 수 있다. HDR 진단 PNG는 1/4 해상도, HDR값/4를 SDR로 표시한 자료로 실제 HDR 화면의 증거가 아니다. HEIC와 JPEG를 직접 감상해야 한다.

원본 ARW 및 카메라 HIF는 읽기 전후 해시·크기·mtime를 확인한다. 원본의 촬영 시간·ISO·셔터·조리개·렌즈 정보가 있는지 확인하고 생성 HEIC/JPEG에서 보존하지 못하는 목록을 보고한다. 현재 포맷은 NCLX 색 정보와 픽셀에 적용한 방향은 유지하지만 촬영 EXIF는 전달하지 않는다. 이는 최종 메타데이터 보존 수용이 아니다. 공개 문서에는 GPS 값이나 촬영 위치를 기록하지 않는다.

## 실제 결과와 시각 검토

대표 5장 모두 새로 생성했고, HEIC 전체 픽셀 독립 검사·ARW/HIF 원본 보존 검사를 통과했다. JPEG 5개도 SDR 디코딩과 Ultra HDR 자체 probe를 통과했다. 모든 SDR 기본 이미지와 JPEG는 8bit, Gain Map은 8bit다. 카메라 HIF는 10bit YUV 4:2:2이며 생성 HEIC SDR은 8bit YUV 4:4:4다.

| 샘플 | 출력 해상도 | HIF bytes | HEIC bytes | JPEG bytes | 독립 HDR 최대 | white>1 픽셀 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| DSC07773 | 4672×7008 | 6,119,424 | 18,783,148 | 7,991,487 | 4.01783 | 34,819 |
| DSC07793 | 7008×4672 | 3,022,848 | 13,117,414 | 5,157,349 | 0.45079 | 0 |
| DSC07796 | 7008×4672 | 8,810,496 | 26,639,877 | 11,099,933 | 0.76709 | 0 |
| DSC07805 | 7008×4672 | 3,801,088 | 14,841,684 | 6,049,283 | 3.72225 | 8 |
| DSC07809 | 4672×7008 | 9,424,896 | 21,205,133 | 10,427,160 | 4.01783 | 934,744 |

꽃/하늘인 DSC07793/DSC07796은 현재 보수적 기본값에서 white>1 픽셀이 0이다. DSC07805도 8개뿐이므로 HDR 표시 판단의 주된 샘플로 쓰지 않는다. Fold7 HDR 판정은 DSC07809와 DSC07773을 우선한다. 수치상 4배 최대값은 양자화/압축 후 4.01783이며 기기 휘도 측정값이 아니다. 5장 shadow 평균 변화량은 0.00000077~0.00001776이었다. 이는 색/노이즈의 사용자 수용을 대신하지 않는다.

Windows Chrome에서 로컬 비교 페이지의 8bit SDR 기본 이미지를 실제 표시했고, 방향·비율·이미지 표시를 확인했다. 모니터 HDR 설정이나 휘도를 계측한 것은 아니다. 5개 PNG 비교와 인물/하늘 600×600의 1:1 픽셀 crop도 확인했다.

- 인물 DSC07773/DSC07805: 카메라 HIF 대비 변환 SDR은 더 어둡고 채도가 낮으며 피부의 붉은 기가 약하다. WB를 camera WB로 적용했어도 Sony 카메라 톤/색 처리와 일치하지 않는다. 과한 전체 밝기 상승은 줄었지만 이 차이를 최종 화질 승인으로 처리하지 않는다.
- 꽃 DSC07793: 꽃잎과 흐린 배경은 구분되고 방향도 맞다. 카메라 대비 낮은 밝기/채도 차이가 있다. HDR 효과를 억지로 추가하지 않았다.
- 하늘 DSC07796: 구름과 나무 경계가 표시된다. 카메라보다 어둡다. 확인한 하늘 1:1 crop에서 뚜렷한 계단형 밴딩은 보이지 않았지만 전체 HDR 화면/모든 계조의 무밴딩 보증은 아니다.
- 인물 1:1 crop: 변환본은 카메라보다 부드럽고 미세 대비가 낮다. 과도하게 부풀린 shadow noise는 눈에 띄지 않았으나, 카메라 sharpening/denoise와 동일하지 않고 야경 노이즈는 평가하지 못했다.
- DSC07809: 세로 방향과 인물/나무/배경 대응이 맞고 그림자가 유지된다. 하이라이트 HDR 감상은 실기기에서 확인해야 한다.

생성된 HEIC/JPEG 5쌍을 다시 읽어 촬영 EXIF가 없음을 확인했다. 원본 HIF 5개에는 촬영 시간·ISO·셔터·조리개·렌즈 정보가 있으며 현재 생성본에서 모두 빠진다. 색 NCLX와 픽셀 방향은 별도 확인했다. 개인정보 값은 보고하지 않는다.

최종 테스트: 실제 RAW 및 새 HEIC를 지정한 전체 suite **13 passed, 0 skipped, 180.73초**. `mypy src` 통과. 보수적 그림자 유지와 같은 의도의 JPEG 비교 생성 테스트를 red→green으로 진행했다. Standards 리뷰는 지적 0건이며 Spec 리뷰에서 요청한 실제 시각 관측을 위에 보완했다. Fold7에서의 HDR 표시·피부색·밴딩·노이즈 최종 승인은 미확인이다.

## Fold7 전달

[실기기 확인 절차](fold7-check.md)에 따라 사용자가 직접 Google 포토 업로드와 육안 평가를 수행한다. 에이전트는 계정 로그인이나 사진 업로드를 하지 않는다. HEIC가 실패하고 JPEG만 성공하면 #4는 실패/미달이며 #5 이후로 넘어가지 않는다.

## 후속 실기기 피드백 (2026-10-22)

사용자는 JPEG만 Ultra HDR로 인식되고 JPEG/HEIC 색이 이상하며 원본 HIF만 정상이라고 보고했다. #3의 파일 준비 완료는 유지하되 현재 톤/색과 HEIC 실기기 호환성은 수용되지 않았다. #4를 열어 두고 추가 진단하며 #5 이후로 진행하지 않는다. 정확한 색 이상 형태와 업로드 전후 파일 대응은 추가 확인 중이다.
